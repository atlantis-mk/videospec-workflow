# Update a production

1. Read `context.md`, `history/index.json`, all affected current artifacts (including `evidence.md`), durable specs, status, and relevant current-conversation instructions. Do not automatically read or inject another production's context.
2. Run `node videospec/bin/videospec.js snapshot <id> --note "before: <reason and affected files>"` before editing.
3. Edit the earliest affected artifact and reconcile dependent artifacts. When later conversation material changes the reference scope, start from v6 `evidence.md`, then `brief.md` and script as needed; do not cosmetically edit an unrelated generated draft. If `assets/audio/voice/narration-lock.json` exists, leave **口播：** text and scene order unchanged unless the user explicitly authorizes a precise revision. For an authorized change, snapshot the old state, record the exact diff, update the protected content files, obtain renewed content approval, then run `generate_voice.py --revise-narration`. The generator archives the prior voice revision and invalidates the old preview and deliverable; rebuild dependent timing, captions, storyboard, preview, and render. Never delete the old revision. Use measured durations in `assets/audio/voice/manifest.json` to time v6 storyboard, subtitles, and render without editing the approved script. When `context.md` or `script.md` declares `Script authority: user-authoritative` or `user-authored`, never modify the user's viewpoints, claims, conclusions, ordering, intended emotional force, rhetorical wording, or fictional story setup unless the user explicitly requests that exact change; record the precise before/after diff and leave the prior source asset intact. For `user-authored`, limited mechanical clarity edits are allowed only when they do not alter those decisions. A changed judgment, hook, audience promise, or pacing may update the v6 brief retention map and storyboard, but does not authorize a script rewrite. Never replace history or silently discard a prior decision.
   When this revision creates or changes narration support, captions, information graphics, or motion, use the current project audio, visual, and creative standards to design the revised storyboard and generate the replacement audio, assets, or composition. Preserve audible access to essential visuals, overlay contrast, chart context and scales, and processing time for dense beats. Reconcile dependent artifacts with those design choices before preview QA; do not defer applying the standards until verification or alter protected narration without renewed content approval.
4. Append operational before/after notes to v6 `activity.md`, then run an `after:` snapshot; update signed `context.md` only when its content decisions actually change, allowing the content approval to become stale. If recording the returned ID modifies the log, take a final snapshot.
5. If the edit changes picture, timing, captions, sound, or referenced media after preview confirmation, mark that confirmation stale. Repeat preview QA, show the updated playable preview, and obtain explicit render confirmation before any re-render. Run lint and status. Approval records remain untouched; any changed signed file requires renewed human approval.

## Automatic continuation

- Before final-video approval, if a review render exists and `publish.md` is incomplete, automatically create or update the release package with title variants, selected title, the separately composed cover assets and distinct search-relevant tag count declared by the current project delivery spec, plus description, metadata, accessibility text, and platform settings. Use `$imagegen` in its built-in generation mode for the covers: make one generation call per ratio, preserve the shared visual concept while adapting each canvas instead of blindly cropping, inspect the result, and move each accepted asset to its declared production-relative cover path. Record the prompt, generator, and final path in `publish.md`. Do not use its CLI fallback unless the user explicitly requests it. Verify that the selected title/cover promise matches the render before asking for final approval. After final approval, do not regenerate routine alternatives; provide the existing package as a compact publication decision brief and stop only for human publication approval.
- After a real human publication record and authorized platform data are available, complete v6 `learning.md` and any evidence-backed standards delta. Do not invent publication results or metrics; absence of authorized data is the only valid reason to wait.

## Artifact authority

Update `evidence.md` first when source scope or factual support changes, `brief.md` when the selected promise or retention design changes, and `script.md` when narration changes are explicitly authorized. Reconcile dependent storyboard and review artifacts. After publication, write the merged result to `learning.md`.
