# VideoSpec automatic controller

Working context is local to the selected production, never copied automatically from a previous episode. Before an AI changes a production artifact, read `context.md`, `activity.md` when present, `history/index.json`, relevant current files, and durable specs; run `videospec snapshot <id> --note "before: ..."`. In v6, `context.md` records decisions protected by the content gate; append operational timing, build, QA, and packaging changes to `activity.md`. A substantive content decision change still updates `context.md` and makes content approval stale. Snapshot the coherent after state; if recording its version ID changes the activity log, take one final snapshot to retain that entry.

On a new or resumed production, inspect status and automatically execute every consecutive non-human phase. Do not ask the user to approve intermediary AI work or select the next AI agent. Continue through each non-human phase and pause at each human gate. The normal chain is:

`conversation/reference triage → brief + evidence ledger → continuous narration → editorial opposition + reference-fidelity audit + video-script-review → revision/re-review as authorized → human content approval → director storyboard + materials → TTS lock + measured timing in voice manifest → playable preview + pre-render QA → explicit human confirmation of the current preview → render → encoded-master and audience-critic review → fixes, renewed preview confirmation, and re-render when needed → title + 16:9/4:3/3:4 covers + description/package + platform draft → human final approval → human publish approval → human publication record → learning → standards sync → archive`

Always read relevant earlier current-conversation instructions, decisions, attachments, links, and referenced-chat material before choosing the topic. Treat user goals, corrections, and discussion as `conversation` sources; treat supplied source material as `extract`; use `adapt` for a requested re-expression. Newly authored narration must sound like self-media: a creator with a point of view talking to a specific person through conflict, story, questions, examples, and turns. Do not generate news copy, a broadcast script, a press release, official-neutral narration, or a formal lecture. A user-supplied subtitle, transcript, or narration is never merely a reference when the user asks to optimize it: classify it as `user-authored-script`, preserve the user's thesis, sequence, claims, conclusions, emotional intent, deliberate rhetoric, fictional plot devices, and user-supplied web material, and make only clearly mechanical edits unless the user approves a precise diff. When the user says it must be followed unchanged, use `authoritative-script` and preserve its words and order verbatim. Fictional characters, composite cases, invented dialogue, and hypothetical scenes are permitted creative devices, not missing evidence or a reason to delete. Any ambiguity about whether they could be mistaken for real people, events, or evidence is an internal production finding only, never an automatic audience-facing disclosure. The user's viewpoints and intentionally strong language in the conversation are editorial decisions; record factual, legal, platform, or reputational risks only in internal production records and never silently dilute or replace the content. A user-provided online claim that lacks independent confirmation must be recorded as source-provided/unverified with its locator; it must not be deleted, treated as false, cause a script rewrite, or generate a viewer-facing warning without explicit instruction. Do not use context-free or “inspiration” creation while relevant conversation content exists. Preserve/reframe each ordinary material unit or explicitly document its omission in v6 `evidence.md` (legacy `reference-analysis.md`), map it to a brief beat, and anchor that beat to exact narration wording. Conversation or reference content does not authorize copying protected third-party words, visuals, or audio, but copyright caution never authorizes silently replacing the user's own approved script or the requested substance with a different topic. Later material in the same conversation is an update to this production, not an instruction to discard earlier context.

## Default Chinese self-media expression profile

Unless the user asks for a different voice, write as a real person talking to someone who is about to make a decision—not as an author summarising a lesson. Start with an observable action and immediate conflict (for example, a hand about to press buy, a bill being compared, or a decision already going wrong), then give a useful judgment within 15 seconds. Do not open with detached author-language such as “先把自己拦一下”, “我们先想一想”, or a polished principle with no lived situation.

Build each section as `specific viewer behaviour or consequence → misconception / tension → condition or mechanism → the next natural question`. Use causal handoffs (“而这时…”, “但更麻烦的是…”, “躲开这个坑以后…”) instead of mechanically opening every section with “第一、第二” or “第 X 个问题”. A numbered checklist may appear as the viewer tool or ending payoff, but it must not make the spoken script sound like a lecture. “自媒体留存” means early value, concrete behaviour, reversals, usable checks, and progress at a pace suited to the target duration (in longer videos, new value roughly every 30–45 seconds); never promise virality or rely on empty excitement.

For TTS, use `speech_rate: 15` as the standard baseline. Slow down only where a condition, risk, contrast, or decision needs room; vary upward only where the spoken thought remains natural. Each scene’s delivery prompt must name the conversational turn, pause, and reason for its speed rather than treating all sections as a uniform announcer read.

Route the first content package to `videospec-propose`; script revisions, release-package repairs, and data records to `videospec-update`; TTS/video production and the first release package to `videospec-apply`; QA to `videospec-verify`; human sign-off to `videospec-approve`; and final validation and archival to this controller. Before any non-dry-run TTS request, finalize the complete **口播：** manuscript and, for legacy scene-based scripts, scene order. That request creates the production narration lock; thereafter no agent may alter spoken text, even for a newly authored script. A completed full TTS run is the timing authority: v6 stores measured timing in the voice manifest without editing the approved script; time the storyboard, captions, and renders from it. Older scene-based scripts retain their header calibration. Invoke `$video-script-review` for the content-review artifact, or apply its exact review contract if it is unavailable. Treat the audience critic as a time-coded editorial hypothesis, never as fabricated platform retention data. Create the release package during production QA, before final approval, so title/cover promise can be compared with the actual master. For publication covers, invoke `$imagegen`: use its built-in generation mode, make one separately composed image per required ratio, and move each accepted output into the current production before recording it in `publish.md`.

Stop for content approval, explicit confirmation of the current playable preview before every render or export, final-video approval, and publication approval. At each gate, present one compact decision brief: default recommendation, one-sentence viewer promise, changed items, unresolved risks, and links to only the relevant viewing artifact. Do not ask the user to select alternatives unless the default is low confidence or conflicts with an approval. Also stop when required external input is genuinely unavailable (for example, no authorized platform analytics or no actual human publication record), or when bounded QA attempts leave a blocking failure; record the dependency or failure without fabricating a pass. QA findings that can be fixed within the approved scope must be fixed and rechecked within the `videospec-verify` retry limits. If a fix changes content protected by an approval, mark it stale and return only to that required human gate. Never overwrite or delete `history/V###`.

## Completion and archive

When `videospec next <id>` reaches standards sync or archive, read the current production's context, history index, publication record, and v6 `learning.md` (legacy analytics and retrospective). Promote only evidence-backed reusable standards through `videospec-sync` when a delta is pending or stale; keep episode-specific context in its history. Run `videospec validate <id>` and resolve every reported issue before `videospec archive <id>`. Never delete, replace, or fabricate snapshots, publication data, tasks, review outcomes, or approvals. The CLI performs final validation again before moving the production; report the resulting archive path.

## v6 artifact authority

Reuse a matching current-conversation `videospec-explore` handoff rather than generating another angle slate. Before costly production work, preflight the selected renderer, built-in `$imagegen`, TTS, subtitle, and inspection capabilities without exposing credentials; record any missing required dependency as a resumable blocker. Limit automatic QA repair loops as specified by `videospec-verify`, retaining unresolved findings instead of retrying indefinitely.

For templateVersion 6, the flow is `brief.md → evidence.md → script.md → content-review.md → content approval → storyboard.md + materials.md → TTS → playable preview + pre-render QA → human render confirmation → render + review.md → publish.md → final/publication approvals → learning.md`. `brief.md` replaces topic plus retention plan; `evidence.md` replaces reference analysis plus research; `learning.md` replaces analytics plus retrospective. `activity.md` is the unsigned operational log. Map each evidence reference to a brief beat and each beat to an exact narration anchor; map storyboard scenes to beats and materials to scenes. Register deliverables inside the production, and verify the three stored cover files before final and publication approval.
