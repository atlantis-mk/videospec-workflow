# VideoSpec automatic controller

Working context is local to the selected production, never copied automatically from a previous episode. Before an AI changes a production artifact, read `context.md`, `activity.md` when present, `history/index.json`, relevant current files, and durable specs; run `videospec snapshot <id> --note "before: ..."`. In v6, `context.md` records decisions protected by the content gate; append operational timing, build, QA, and packaging changes to `activity.md`. A substantive content decision change still updates `context.md` and makes content approval stale. Snapshot the coherent after state; if recording its version ID changes the activity log, take one final snapshot to retain that entry.

On a new or resumed production, inspect status and automatically execute every consecutive non-human phase. Do not ask the user to approve intermediary AI work or select the next AI agent. Continue through each non-human phase and pause at each human gate. The normal chain is:

`conversation/reference triage → brief + evidence ledger → continuous narration → editorial opposition + reference-fidelity audit + video-script-review → revision/re-review as authorized → human content approval → director storyboard + materials → TTS lock + measured timing in voice manifest → playable preview + pre-render QA → explicit human confirmation of the current preview → render → encoded-master and audience-critic review → fixes, renewed preview confirmation, and re-render when needed → title + project-required covers + description/package + platform draft → human final approval → human publish approval → human publication record → learning → standards sync → archive`

Always read relevant earlier current-conversation instructions, decisions, attachments, links, and referenced-chat material before choosing the topic. Treat user goals, corrections, and discussion as `conversation` sources; treat supplied source material as `extract`; use `adapt` for a requested re-expression. For newly authored narration, apply the current project creative spec. A user-supplied subtitle, transcript, or narration is never merely a reference when the user asks to optimize it: classify it as `user-authored-script`, preserve the user's thesis, sequence, claims, conclusions, emotional intent, deliberate rhetoric, fictional plot devices, and user-supplied web material, and make only clearly mechanical edits unless the user approves a precise diff. When the user says it must be followed unchanged, use `authoritative-script` and preserve its words and order verbatim. Fictional characters, composite cases, invented dialogue, and hypothetical scenes are permitted creative devices, not missing evidence or a reason to delete. Any ambiguity about whether they could be mistaken for real people, events, or evidence is an internal production finding only, never an automatic audience-facing disclosure. The user's viewpoints and intentionally strong language in the conversation are editorial decisions; record factual, legal, platform, or reputational risks only in internal production records and never silently dilute or replace the content. A user-provided online claim that lacks independent confirmation must be recorded as source-provided/unverified with its locator; it must not be deleted, treated as false, cause a script rewrite, or generate a viewer-facing warning without explicit instruction. Do not use context-free or “inspiration” creation while relevant conversation content exists. Preserve/reframe each ordinary material unit or explicitly document its omission in `evidence.md`, map it to a brief beat, and anchor that beat to exact narration wording. Conversation or reference content does not authorize copying protected third-party words, visuals, or audio, but copyright caution never authorizes silently replacing the user's own approved script or the requested substance with a different topic. Later material in the same conversation is an update to this production, not an instruction to discard earlier context.

## Creative direction

Read `videospec/specs/creative/spec.md` for the project's narration tone and retention standards. Apply those standards when routing content creation and review; record production-specific delivery choices in `script.md` and `brief.md`.

Route the first content package to `videospec-propose`; script revisions, release-package repairs, and data records to `videospec-update`; TTS/video production and the first release package to `videospec-apply`; QA to `videospec-verify`; human sign-off to `videospec-approve`; and final validation and archival to this controller. Before any non-dry-run TTS request, finalize the complete **口播：** manuscript. That request creates the production narration lock. A later user-authorized narration change requires a precise diff, renewed content approval, and `generate_voice.py --revise-narration`; the generator archives the prior voice revision and invalidates the old preview and deliverable. A completed full TTS run is the timing authority: the generator stores measured timing in the voice manifest without editing the approved script; time the storyboard, captions, and renders from it. Invoke `$video-script-review` for the content-review artifact, or apply its exact review contract if it is unavailable. Treat the audience critic as a time-coded editorial hypothesis, never as fabricated platform retention data. Create the release package during production QA, before final approval, so title/cover promise can be compared with the actual master. For publication covers, invoke `$imagegen`: use its built-in generation mode, make one separately composed image per required ratio, and move each accepted output into the current production before recording it in `publish.md`.

Stop for content approval, explicit confirmation of the current playable preview before every render or export, final-video approval, and publication approval. At each gate, present one compact decision brief: default recommendation, one-sentence viewer promise, changed items, unresolved risks, and links to only the relevant viewing artifact. Do not ask the user to select alternatives unless the default is low confidence or conflicts with an approval. Also stop when required external input is genuinely unavailable (for example, no authorized platform analytics or no actual human publication record), or when bounded QA attempts leave a blocking failure; record the dependency or failure without fabricating a pass. QA findings that can be fixed within the approved scope must be fixed and rechecked within the `videospec-verify` retry limits. If a fix changes content protected by an approval, mark it stale and return only to that required human gate. Never overwrite or delete `history/V###`.

## Completion and archive

When `videospec next <id>` reaches standards sync or archive, read the current production's context, history index, publication record, and `learning.md`. Promote only evidence-backed reusable standards through `videospec-sync` when a delta is pending or stale; keep episode-specific context in its history. Run `videospec validate <id>` and resolve every reported issue before `videospec archive <id>`. Never delete, replace, or fabricate snapshots, publication data, tasks, review outcomes, or approvals. The CLI performs final validation again before moving the production; report the resulting archive path.

## v6 artifact authority

Reuse a matching current-conversation `videospec-explore` handoff rather than generating another angle slate. Before costly production work, preflight the selected renderer, built-in `$imagegen`, TTS, subtitle, and inspection capabilities without exposing credentials; record any missing required dependency as a resumable blocker. Limit automatic QA repair loops as specified by `videospec-verify`, retaining unresolved findings instead of retrying indefinitely.

The flow is `brief.md → evidence.md → script.md → content-review.md → content approval → storyboard.md + materials.md → TTS → playable preview + pre-render QA → human render confirmation → render + review.md → publish.md → final/publication approvals → learning.md`. `activity.md` is the unsigned operational log. Map each evidence reference to a brief beat and each beat to an exact narration anchor; map storyboard scenes to beats and materials to scenes. Register deliverables inside the production, and verify every cover declared in the current project delivery spec before final and publication approval.
