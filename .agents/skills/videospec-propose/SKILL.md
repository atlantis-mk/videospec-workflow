# Propose a production

1. Create the production. Its `history/V000` baseline is created automatically. Before drafting, read the relevant prior turns in the current conversation: user goals, corrections, decisions, pasted material, attachments, links, and referenced chats. They are current-production input, not another episode's working context. Reuse a `videospec-explore` handoff from that conversation when its sources and constraints still match; record its locator and recheck any changed facts or constraints rather than repeating the angle search.
2. Treat relevant current-conversation content as the required source by default. Use `conversation` for user goals, decisions, corrections, and discussion; use `extract` for supplied transcript/article/video/other source material; use `adapt` only when the user requests a new expression of the same substance. **If the user says a supplied subtitle, transcript, or narration is “为准”, “按原稿”, “不要改”, or equivalent, classify it as `authoritative-script`. If the user supplies a script and asks to “优化”, “润色”, “提升口播感”, or equivalent, classify it as `user-authored-script`, not as a reference.** Both kinds of user script override rewrite, reframe, originality, style, and finance-normalisation defaults. The user's views, judgments, conclusions, intentional emotional intensity, rhetorical choices, and fictional narrative devices stated anywhere in the conversation are user-authoritative editorial decisions; record them as such rather than substituting a model's view. There is no `inspire` or context-free original path while relevant conversation content exists.
3. Snapshot with a `before:` note, then complete v6 `context.md`, `brief.md`, `evidence.md`, and `script.md` (use the recorded legacy layout only for older productions). For open-ended ordinary work without a matching exploration handoff, generate 8–12 distinct angles before recording the selected one-sentence judgment. Reuse a matching exploration slate; when the user has already fixed a direction or supplied a protected script, record that direction and its source in the v6 `brief.md` Angle slate section without generating competing topics. Write newly authored scripts as a creator talking to one specific viewer: open on an observable decision or consequence, give a useful judgment within 15 seconds, then use concrete behaviour → tension → mechanism/condition → next natural question to carry each section. Do not generate a news report, broadcast bulletin, official statement, press release, formal explanatory copy, author-style summaries, or a spoken “first/second/third” lecture. A numbered tool is for the viewer’s action or ending payoff, not the rhythm of every spoken scene. Use `speech_rate: 15` as the base; document one coherent v6 voice profile and purposeful pauses; use scene-specific controls only for older scripts. For `authoritative-script` work, record the source locator, local asset path when available, checksum when obtainable, the exact user instruction, and `Script authority: user-authoritative`; preserve narration verbatim in scene order. For `user-authored-script` optimization, record `Script authority: user-authored`, preserve the user's thesis, claims, conclusions, sequence, emotional intent, deliberate rhetorical intensity, and fictional story setup, and optimize only clarity, spoken flow, sentence segmentation, redundancy, and pacing. Never turn optimization into a different argument or a newly authored script. Every proposed content-level change must be shown as a precise diff before it is applied; absent explicit authorization, automatically apply only uncontroversial punctuation, typo, and caption-break corrections. In either user-script mode, v6 may add narration anchors in `brief.md`, scene IDs and timing in `storyboard.md`, TTS parameters, visual direction, and evidence notes without changing spoken words; older scripts may add scene IDs and timestamps to their script metadata. Keep risk, verification, and narrative-status metadata out of `script.md`; record it only in internal production records. In v6 `brief.md`, design visual/audio treatment around the user script; it does not authorize changing it. In v6 `evidence.md`, record each other material reference unit with its conversation/source locator, normalized idea, verification status, preserve/reframe/omit decision, and brief-beat coverage. An omission requires a concrete rationale.
4. Treat ordinary conversation and supplied material as the required content scope, not as wording to copy. Rephrase the expression and build an original structure where useful, but retain or transparently omit the material ideas under discussion. This rule never applies to an `authoritative-script` or `user-authored-script`: the user's script and editorial decisions are production content, not material to imitate. **Fictional storytelling is permitted.** A fictional character, composite, hypothetical situation, invented dialogue, or dramatic scene may carry the entire narrative and needs no personal-experience proof, research citation, or deletion recommendation. Record it as `fictional`, `composite`, or `hypothetical`. If it could reasonably be mistaken for an identifiable real person, a documented real event, or factual evidence, record that observation **only in internal production records**. Never add a disclosure, risk label, verification note, or narrative-status label to narration, subtitles, screen text, visual prompts, assets, title, cover, description, or any other audience-facing output unless the user explicitly asks for it. Never remove a fictional device unless the user asks. **Keep verification status separate from editorial authority.** A claim, case, quote, or observation supplied by the user from the web remains in scope even if independent verification is unavailable: record its original URL/locator, date when known, and status such as `source-provided — independently unverified`; do not label it false or delete it merely because a second source was not found. For either user-script mode, factual, legal, platform, or reputational risks are internal annotations only: store them in `context.md`, v6 `evidence.md`, `content-review.md`, or `review.md` (legacy research/reference-analysis files remain valid), never in audience-facing output. Even deliberate hyperbole, sharp language, or emotional wording must be flagged with a reason and optional alternative, never silently softened, removed, or replaced. Only an explicit user instruction may authorize omission, a content-level rewrite, or a viewer-facing disclosure. Do not reuse unrelated source audio, images, screenshots, or distinctive expression without rights.
5. Run a reference-fidelity audit before the normal script review: every non-omitted reference unit must map to a brief beat anchored to exact narration wording in v6 (or real script scenes in older templates), the stated title and promise must match the requested reference scope, and any scope change must be explicit. Record coverage, omissions, conversation decisions, source provenance, and rights/verification risks in `content-review.md`. A missing material unit or an unapproved topic substitution is `REWRITE`. Lack of independent confirmation is a verification annotation, never an omission decision.
6. Before the normal script review, run an editorial-opposition pass: steelman the strongest objection to the selected judgment, identify missing evidence or qualifications, and distinguish them from empty both-sides hedging. Then automatically invoke `$video-script-review` on the completed script and write its evidence-based result into `content-review.md`: all eight scores, overall score, likely exit point, severity-ranked quoted issues, revision directions, preserved strengths, and PASS/REVISE/REWRITE. The reviewer diagnoses; it does not rewrite the script.
7. The review must also audit v6 brief retention-map fidelity (legacy retention-plan fidelity), AI cliches, article-like exposition, news-report/broadcast cadence, official-neutral boilerplate, flat emotional rhythm, unsupported irony, narration copied into screen text, missing viewer dialogue, and a stretch without a new question, information, example, counterpoint, or payoff that is too long for the target duration (including 20–30 seconds in longer videos). Specifically flag an opening that starts with an abstract conclusion rather than a recognisable action/conflict, “作者替观众下判断” phrases that nobody would naturally say in conversation, and repeated “第 X 个问题” openings that turn a useful checklist into a lecture. A neutral “first/second/finally + information recap” structure, overly complete sentences, and impersonal institutional phrasing are defects when they make the narration feel like a bulletin rather than self-media. For ordinary work, revise the earliest affected artifact when either audit identifies a fixable issue. For `authoritative-script` and `user-authored-script` work, reviews diagnose only for viewpoints, claims, conclusions, sequence, fictional plot devices, web-sourced material, and emotional/rhetorical language: write issues, risks, provenance gaps, and optional alternatives in internal production records without modifying narration or directing any viewer-facing label. A fictional device is not a defect because it is not personal experience. `Unverified`, `not independently confirmed`, or similar labels must never trigger deletion. Automatically revise only non-verbal artifacts and explicitly authorized mechanical corrections. Escalate every proposed content-level narration change, including a factual correction, a removed fictional device, an omitted web-sourced claim, or a softened "过激" expression, to the human content gate with a precise diff. Limit ordinary automatic revision to two coherent passes; escalate unresolved critical/high issues or a `REWRITE` judgment to the human content gate as explicit risks. Snapshot before and after every coherent revision.
8. When the user supplies or corrects relevant material later in the same conversation, treat it as a source update: snapshot, update v6 `evidence.md` (legacy `reference-analysis.md`), preserve or replace the authoritative script only to the extent the user explicitly directs, rebuild dependent artifacts, and re-run audits. Do not ask the user to restate earlier conversation content. If a content approval exists, allow it to become stale and return only to that gate.
9. In `context.md`, append the before/after narrative, reference mode, coverage/omissions, decisions, sources, risks, the `content-review.md` locator, and changed assumptions; keep numeric review scores only in `content-review.md`. Do not remove earlier entries. Snapshot with `after:`. If recording that returned version ID changes the ledger, take a final `after-context:` snapshot.
10. Run lint and status, then stop only to request explicit human `content` approval. Present a single decision brief with the selected angle, first-15-second promise, full narration, review verdict, source/rights exceptions, and one default recommendation. Do not make the user select an AI tool, a next step, or among routine angle/script variants; show alternatives only when the leading angle is low confidence or conflicts with the requested scope. Never fabricate sources, mapping, rights, or approvals.

## v6 artifact authority

For templateVersion 6, use `brief.md` as the single source for topic, selected promise, angle slate, retention beats, and success hypothesis. Use `evidence.md` as the single source for reference coverage, research, provenance, rights, and verification. Do not create or update `topic.md`, `reference-analysis.md`, `retention-plan.md`, or `research.md` for a v6 production. Keep `script.md` and `content-review.md` separate because narration and the content gate have different authority.
