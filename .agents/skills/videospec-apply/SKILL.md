# Apply an approved production

1. Read the current production's context ledger, history, and `reference-analysis.md` when present. Require valid `content` approval; do not import another episode's working context. Before costly generation, check that the selected video renderer, TTS credential and Python voice dependencies, subtitle dependencies, and audio/video inspection tools needed for this production are available. Check `$imagegen` built-in generation when this template requires publication covers. Check credential presence without printing its value. If a required capability is missing, take a `before:` snapshot, record the exact dependency and resumable step in v6 `activity.md` (legacy `tasks.md`), take an `after:` snapshot, and report the blocker; do not fabricate media or claim that QA ran. Once prerequisites are available, proceed through all production steps without requesting intermediate approval.
2. Snapshot `before:` any storyboard, materials, TTS, task, or build-artifact change. Read the approved v6 `brief.md` (legacy `retention-plan.md`) and act first as a self-media director, then as a builder. If `script.md` declares `Script authority: user-authoritative` or `user-authored`, narration and the generated subtitle track must retain the user's approved views, conclusions, rhetoric, and scene order. For `user-authoritative`, reproduce spoken words verbatim; for `user-authored`, only an explicitly approved diff may change content-level wording. Visual improvements, caption line breaks, and timing may not change wording. Safety, verification, source-status, and fictional-status findings are internal metadata only: never turn them into spoken text, captions, screen text, visual prompts, image/video assets, character dialogue, titles, covers, descriptions, or disclaimers unless the user explicitly requests an audience-facing disclosure. Automatically complete storyboard, materials, TTS, video build, and task records with traceable source and rights records. Every storyboard scene must state its visual mode, attention task, visual/audio beat, and acceptance check. Do not convert narration sentence-by-sentence into subtitle cards: screen text is only for keywords, numbers, conflict, or conclusion; use footage, interfaces, examples, comparisons, data, and visual metaphors when they communicate more. The storyboard and materials must implement the approved script’s mapped reference substance, not the source’s protected images, audio, screenshots, or distinctive sequence.
3. Inspect the plan with `python3 videospec/scripts/generate_voice.py <production>/script.md --dry-run`. Before the first non-dry-run TTS request (including a representative `--scene MASTER` sample for v6 or `--scene S001` for older scripts), finalize every blockquoted **口播：** field and scene order. The generator writes `assets/audio/voice/narration-lock.json` before synthesis; afterward it rejects any changed spoken text or order. A full v6 run records measured timing only in `assets/audio/voice/manifest.json`, leaving the content-approved `script.md` unchanged; older scene-based scripts retain timecode calibration. Reconcile storyboard, captions, and other timing-only artifacts from that measured source; do not use timing calibration as a reason to edit narration. Direct the voice as a human creator speaking to one person—conversational, varied, with thought, pause, contrast, and emotional turns—not as a newscaster, announcer, official reader, or formal presenter. `speech_rate: 15` is the v6 master-narration baseline; set one coherent rate and describe purposeful delivery changes in the global voice prompt. Older scene-based scripts may vary rate per scene when justified. The generator keeps the raw v6 master or legacy scene segments, then applies a 75 Hz high-pass, gentle de-essing, 2.5:1 speech compression and a -1.5 dB safety limiter to each segment. It joins legacy scenes in script order when needed and uses two-pass EBU R128 mastering to create the only usable voice master, `assets/audio/voice/narration.wav` (mono 48 kHz / 24-bit PCM WAV, -16 LUFS, 6 LU LRA, -1.5 dBTP). The video build may use only this merged file, never raw segments. After music and effects are added, master the final stereo video mix to -14 LUFS and -1.0 dBTP. The generator reads the init-created local secret file or `VOLCENGINE_TTS_API_KEY`; never place a key in an artifact, snapshot, command output, or prompt. Export timed ASR subtitles from the merged narration with `python3 videospec/scripts/export_subtitles.py <production>/assets/audio/voice/narration.wav --output <production>/assets/audio/voice/subtitles/narration.asr.srt`; retain the SRT and `.asr.json` result. When the script wording is authoritative, correct the ASR wording from that timed SRT with `--correct-srt` and `--canonical-script` for v6 or `--canonical-srt` for older productions; save the corrected delivery SRT separately. Build the approved scenes and register the review render.
4. Append operational before/after notes to v6 `activity.md` (legacy `context.md`), then snapshot `after:` the coherent build. Change `context.md` in v6 only for a substantive content decision, which makes content approval stale. If recording the returned ID changes the log, take a final snapshot.
5. After registering the review render, automatically create the initial `publish.md` in the same production run: select a default title, generate and inspect three separately composed native-ratio covers (16:9, 4:3, 3:4) with `$imagegen`, and prepare description, metadata, tags, accessibility text, platform settings, and a platform draft. Do this before final approval so the title and cover promise can be checked against the actual master. Rank options internally and surface alternatives only for low confidence or a conflict with the approved content. Run lint/status and automatically hand both the render and release package to `videospec-verify` in the same production run. Never impose a mechanical cut interval or permanent high-energy delivery; vary visual and audio treatment only where a retention beat calls for it. Never approve a human gate.

## v6 artifact authority

For templateVersion 6, read the approved `brief.md` and `evidence.md`. Build storyboard scenes against brief beat IDs, and materials against storyboard scene IDs. `brief.md` controls the viewer promise and retention map; `script.md` controls narration; `storyboard.md` controls visual implementation; `materials.md` controls provenance and rights. Complete `learning.md` only after publication and authorized data are available.

For templateVersion 6 subtitle correction, pass `--canonical-script <production>/script.md` to `export_subtitles.py`; it extracts the ordered blockquoted **口播：** fields while retaining the ASR cue timings. Use `--canonical-srt` for older productions whose canonical wording is stored in a separate SRT.
