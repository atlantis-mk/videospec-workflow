# Apply an approved production

For narrated Chinese finance videos, use any finance-video-production skill supplied by the current project for media sourcing, image pacing, source-video headroom, and clean preview acceptance. The general VideoSpec checks below apply in every project.

1. Read the current production's context ledger, history, `evidence.md`, and the project's audio, visual, creative, and delivery specs. Require valid `content` approval; do not import another episode's working context. Before costly generation, check that the selected video renderer, TTS credential and Python voice dependencies, subtitle dependencies, and audio/video inspection tools needed for this production are available. Check `$imagegen` built-in generation when this template requires publication covers. Check credential presence without printing its value. If a required capability is missing, take a `before:` snapshot, record the exact dependency and resumable step in `activity.md`, take an `after:` snapshot, and report the blocker; do not fabricate media or claim that QA ran. Once prerequisites are available, proceed through the playable preview and pre-render QA; request explicit human confirmation of that current preview before rendering.
2. Snapshot `before:` any storyboard, materials, TTS, task, or build-artifact change. Read the approved `brief.md` and act first as a self-media director, then as a builder. If `script.md` declares `Script authority: user-authoritative` or `user-authored`, narration and the generated subtitle track must retain the user's approved views, conclusions, rhetoric, and scene order. For `user-authoritative`, reproduce spoken words verbatim; for `user-authored`, only an explicitly approved diff may change content-level wording. Visual improvements, caption line breaks, and timing may not change wording. Safety, verification, source-status, and fictional-status findings are internal metadata only: never turn them into spoken text, captions, screen text, visual prompts, image/video assets, character dialogue, titles, covers, descriptions, or disclaimers unless the user explicitly requests an audience-facing disclosure. Automatically complete storyboard, materials, TTS, video build, and task records with traceable source and rights records. Every storyboard scene must state its visual mode, attention task, visual/audio beat, and acceptance check. Do not convert narration sentence-by-sentence into subtitle cards: screen text is only for keywords, numbers, conflict, or conclusion; use footage, interfaces, examples, comparisons, data, and visual metaphors when they communicate more. The storyboard and materials must implement the approved script’s mapped reference substance, not the source’s protected images, audio, screenshots, or distinctive sequence.
3. Inspect the plan with `python3 videospec/scripts/generate_voice.py <production>/script.md --dry-run`. Before the first non-dry-run TTS request (including a representative `--scene MASTER` sample), finalize every blockquoted **口播：** field and scene order. The generator writes `assets/audio/voice/narration-lock.json` before synthesis; afterward it rejects changed spoken text or order unless the user-authorized revision has renewed content approval and runs with `--revise-narration`. A full run records measured timing only in `assets/audio/voice/manifest.json`, leaving the content-approved `script.md` unchanged. Reconcile storyboard, captions, and other timing-only artifacts from that measured source; do not use timing calibration as a reason to edit narration. Direct the voice according to the current project creative spec and approved script. Set one coherent rate in the approved script and describe purposeful delivery changes in the global voice prompt. The generator reads the project's `videospec/specs/audio/spec.md` audio profile, retains raw narration, and creates the processed voice master at `assets/audio/voice/narration.wav`. Use that master for the video build, and check the final mix against the same project profile. Record the applied profile and its source hash in the voice manifest. The generator reads the init-created local secret file or `VOLCENGINE_TTS_API_KEY`; never place a key in an artifact, snapshot, command output, or prompt. Export timed ASR subtitles from the merged narration with `python3 videospec/scripts/export_subtitles.py <production>/assets/audio/voice/narration.wav --output <production>/assets/audio/voice/subtitles/narration.asr.srt`; retain the SRT and `.asr.json` result. When the script wording is authoritative, correct the ASR wording from that timed SRT with `--correct-srt` and `--canonical-script`; save the corrected delivery SRT separately. Build the approved scenes, playable preview, and pre-render QA. Record hashes of `script.md`, the composition, corrected subtitles, narration master, voice manifest, and every referenced local media file.
4. Present a clean playable preview only after passing pre-render QA. For HyperFrames, launch the lightweight viewer with `npx hyperframes play` and use its plain URL for agent review and user confirmation; do not start the Studio editor unless timeline editing or selection context is needed. Record the preview URL, QA evidence, input hashes, and current version in `render-authorization.json`, initially with `approved: false`. Wait for the user to explicitly confirm that exact preview may be rendered. Record the user and timestamp only after that decision; then run `python3 videospec/scripts/check_render_authorization.py <production>` immediately before each video render or export. If a preview-affecting input changes, repeat QA, show the new preview, and obtain confirmation again. Render and register the review deliverable only after the check passes. Append operational before/after notes to `activity.md`, then snapshot `after:` the coherent build. Change `context.md` only for a substantive content decision, which makes content approval stale. If recording the returned ID changes the log, take a final snapshot.
5. After registering the authorized review render, automatically create the initial `publish.md` in the same production run: select a default title, generate and inspect each cover variant declared by the current project delivery spec with `$imagegen`, and prepare description, metadata, tags, accessibility text, platform settings, and a platform draft. Do this before final approval so the title and cover promise can be checked against the actual master. Rank options internally and surface alternatives only for low confidence or a conflict with the approved content. Run lint/status and automatically hand both the render and release package to `videospec-verify` in the same production run. Never impose a mechanical cut interval or permanent high-energy delivery; vary visual and audio treatment only where a retention beat calls for it. Never approve a human gate.

## Apply project standards

Before designing scenes, caption tracks, charts, or effects, read the current `videospec/specs/audio/spec.md`, `videospec/specs/visual/spec.md`, and `videospec/specs/creative/spec.md` as production constraints. Map essential visual meaning to approved audio or an authorized description path; do not rewrite protected narration. Decide the caption treatment and meaningful sound/speaker cues, maintain overlay contrast on changing backgrounds, preserve factual chart context and honest scales, add non-color cues, choose motion that satisfies the flash standard, and allow processing time for dense information. Write those choices into `storyboard.md` and `materials.md` where relevant, then implement them in the generated captions, assets, audio, and composition; an after-the-fact checklist alone does not satisfy a standard. Turn each applicable `Check` into an acceptance check at its specified stage and carry it into `tasks.md`, even when an older production's task template has no matching checkbox. Mark an inapplicable check with its reason. Inspect the playable preview at the required size and relevant timecodes, record evidence and failures in `tasks.md`, and fix failed agent checks before offering the preview for render confirmation. For a check reserved for a human reviewer, prepare evidence and leave the decision pending. Do not claim a flash-threshold exception without a measurement that meets the project standard.

## Pre-render preview QA

Check the renderer's runtime, layout, motion, and contrast on the final preview; inspect the opening, ending, each media handoff, and risky semantic transitions in both seeked frames and continuous playback. Compare corrected subtitles and semantic element entry points with locked narration and reliable word times. Check caption exits, mobile readability, black or empty frames, timeline gaps, source-video headroom, and media motion. Record evidence and input hashes in `tasks.md`. Fix failures before requesting render confirmation. Rendered-file QA later checks the encoded result; any re-render after changed inputs needs a new preview and confirmation. For new HyperFrames builds, use one `data-track-kind="captions"` sub-composition track with phrase groups and a deterministic hide at each group end; do not create one root-level HTML clip per SRT cue.

## Artifact authority

Read the approved `brief.md` and `evidence.md`. Build storyboard scenes against brief beat IDs, and materials against storyboard scene IDs. `brief.md` controls the viewer promise and retention map; `script.md` controls narration; `storyboard.md` controls visual implementation; `materials.md` controls provenance and rights. Complete `learning.md` only after publication and authorized data are available.

For subtitle correction, pass `--canonical-script <production>/script.md` to `export_subtitles.py`; it extracts the ordered blockquoted **口播：** fields while retaining the ASR cue timings.
