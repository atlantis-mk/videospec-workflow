# 财经视频制作

用于 VideoSpec 项目新片制作；已有 production 从当前阶段接续，保留已批准内容和用户当轮要求。普通财经问答、参考片评估和发布数据分析不触发。遵守当前项目的事实、字幕锚点和人工审核要求；使用 VideoSpec 时按 `videospec-apply` 执行版本记录和渲染授权。

## 画面设计

- 默认借鉴参考片的表达机制：人物或处境反差、生活化场景、贯穿物件、问题递进、写实分镜、关键词大字和短句字幕。按本期论证取舍，不强制人物数或章节数。
- 从最终旁白和校正字幕拆出语义镜头；每次行为、关系、例子、因果步骤或结论改变时，安排对应的画面。主画面优先解释当句，图表和界面可代替情景图。
- 每张情景图片在全片只用一次，不把同一文件裁剪、调色或换转场后当作新镜头复用。单张图片的连续可见时间不超过 4 秒；需要更长解释时换不同素材、图表、局部细节或动态视频。镜头交接可以短暂重叠。
- 不在情景图片或视频上叠黑色半透明蒙版，也不使用让素材整体发灰的全画幅暗色遮罩。文字可放在画面留白、局部不透明浅色卡片或独立版式上，确保手机尺寸可读。

## 素材顺序与记录

1. 先用 Pexels API key 搜索候选**图片和视频**，按每个语义镜头的场景、动作、构图与画幅判断是否合适；不要只凭搜索词命中就采用。密钥只从本机安全配置或环境变量读取，不写进日志、文档或命令输出。
2. 对找不到合适 Pexels 素材的镜头，才使用 `$imagegen` 的内置工具生成项目图片；遵守该技能的保存和检查流程。需要动态语义时继续寻找合适且可用的视频，不能用一张生成图长时间顶替。
3. 其他图片或视频搜索可以作为补充，但采用前要核对来源、使用权限和画面适配。将最终素材的来源链接、作者、用途、文件路径及必要的许可信息写入 `materials.md`；下载到当前 production，使预览不依赖远程链接。

## 时间线验收

- 以最终旁白和字幕锚点排镜头。相邻主画面必须连续覆盖整段时间线；交叉淡入时下一镜应在上一镜结束前进入，不能出现空白或纯色等待。
- 对每段素材视频，读取文件的实际时长、媒体起点和播放速度，核算实际消耗的源片时长。计划播放必须在源片结束前留至少 0.25 秒余量；下一镜应在视频时间线片段结束前进入（硬切则同帧接上）。不允许视频播完后靠末帧停住等待下一镜。
- 在提交预览前，自动检查图片复用、单图最长可见时间、相邻镜头空档、视频源片余量；再抽查每个视频交接前后画面，确认没有停帧、黑场或意外灰蒙版。发现问题先修复，再更新预览。

## 字幕制作与渲染

- 新片字幕按 `$media-use` 的 captions authoring / motion 规则和 `$hyperframes-studio` 的字幕轨约定制作。最终旁白音频决定时间，人工校正的原稿决定文字；保留可靠词级时间，按自然短句或停顿分组。仅有 SRT 的句级时间时，先对齐词级时间再制作逐词强调，不能把整句 cue 起点冒充每个词的入点。
- 在 HyperFrames 中使用一个专用的 captions 子组合宿主（`data-track-kind="captions"`），把所有字幕组按顺序放在同一轨。不要在根组合为每条 SRT cue 建一个普通 HTML `clip`/字幕卡片，把文本当场景元素逐条叠加。字幕是随旁白变化的字幕层；关键词大字、图解标签属于独立信息画面，不代替完整字幕。
- 每次只显示一组字幕；按词级时间驱动组内强调，组末做确定性退出并在结束时强制隐藏，跳转/逐帧渲染也不得残留或重叠。字幕保持在标题安全区，按手机尺寸检查断行、字宽、遮挡和实际导出字体；自定义中文字体随项目打包，不依赖本机安装。
- 在请求渲染确认前，对字幕轨运行 HyperFrames lint/check，并抽查片头、长句、停顿、关键词前后、镜头交接和结尾的预览帧与实际播放；确认文字、词级入点、退场和旁白同步。渲染后只复查编码结果。现有已完成视频保持其原有审批状态；若用户要求返工，再按此规则检查。

## 渲染前的预览检查

- 用 `$hyperframes` 的 `npx hyperframes check` 检查运行时、布局、动效和对比度，再用 `timeline --json` 核对全片覆盖、镜头交接与素材时长。对片头片尾、每段视频交接和风险转场抓取锚点前后帧；纯播放页实际检查字幕、配音、画面同步、黑/空白帧和手机尺寸可读性。`check` 通过不能代替这些专项检查。
- 用最终旁白、校正字幕和可靠词级时间核对原稿文字、cue 顺序及所有语义元素的入点；检查旁白与时间线的起点和关键段落同步。读取每段视频的源时长、起点、播放速度和关键帧情况，处理可能在预览或逐帧读取中停住的源片。
- 把上述结果、发现和对应的预览输入版本记录在 production 的渲染前任务/检查记录里。任何未完成或未通过项先修复并重新提供预览，不能留到渲染后才首次发现。导出后仍复核编码文件的黑场、声音响度、音画同步和素材运动，作为成品回归检查。

## 先预览，后渲染

- 提供可播放、无编辑控制台或调试面板的纯播放预览入口，让用户直接检查画面、字幕、声音和节奏。静态截图可以辅助检查，但不能代替可播放预览。
- 在用户针对**当前版本预览**明确说可以渲染之前，不运行任何视频渲染或导出，包括 review render、批量渲染和重渲染。内容批准、“继续下一阶段”、打开预览或自动检查通过都不是渲染授权。
- 记录预览版本及用户决定。凡是修改会影响成片的画面、时间线、字幕或声音，重新提供预览并取得新的渲染确认。VideoSpec 项目还须通过 `check_render_authorization.py` 门槛。
