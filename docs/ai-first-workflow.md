# AI 优先的视频生产运行稿

本文描述目标运行方式。当前仓库用 AI 技能编排和 CLI 状态校验实现单期制作；持续选题与 24h / 72h / 7d 定时学习尚无独立调度器，需由外部自动化触发。

## 目标

让一个选题或固定栏目 Brief 自动推进至可发布状态，人工只作 **三次决策**：内容、成片、发布。人工不再选择下一步 AI、不再在环节间复制资料、不再审核中间件、更不需要手动拼标题/封面包。

三道关保留，是因为它们分别承担编辑、声誉与账号发布责任；两关之间则是一条可自动修复、自动复检的连续 AI 作业。

## 运行流程

```text
栏目策略 + 来源库 + 已授权的历史表现数据
                    │
                    ▼
         AI 选题引擎（持续或定时运行）
开放式候选池 / 已确定方向 → 观众价值与证据可行性 → 默认选中或确认角度
                    │
                    ▼
           AI 内容引擎（一趟连续完成）
调研 + 论据账本 + 留存设计 + 脚本 + 反方审稿
                 + 自动修订 + 内容决策简报
                    │
             【人工把关①：内容】
                    │
                    ▼
          AI 制作引擎（一趟连续完成）
导演分镜 + 权利可追溯素材 + TTS 锁稿 + 实测时长
字幕 + 渲染 + 观众代理审片 + 技术 QA + 自动修复/重渲
       + 默认标题 + 三种原生比例封面 + 简介 + 平台草稿
                    │
             【人工把关②：成片】
                    │
                    ▼
          AI 发布引擎（一趟连续完成）
          校验草稿 + 建议排期 + 发布决策简报
                    │
             【人工把关③：发布】
                    │
                    ▼
             人工完成平台最终发布并确认记录
                    │
                    ▼
          AI 学习引擎（24h / 72h / 7d 定时）
读取授权数据 → 复盘 → 单变量实验建议 → 有证据才更新选题策略
```

栏目已有选题策略时，AI 直接选择最高分候选；否则输出排序候选，但把选题判断并入“内容关”，不新增第四个审批点。

## 相比原流程的变化

| 原来的手工感交接 | AI 优先替代方式 |
|---|---|
| 逐一触发选题、调研、写稿、审稿 | 合成一次内容引擎运行；审稿发现自动回到最早受影响产物修订。 |
| 分别审分镜、素材、TTS、成片 | 内容通过后一次跑完制作引擎；只交付可审片成片与简短例外清单。 |
| 成片通过后再制作标题、封面、简介、标签 | 在成片 QA 同时生成并校验完整发布包；成片关看到的就是实际承诺，发布关只剩“是否发布”。 |
| 人工从每个 AI 备选中做选择 | AI 排序并默认选中；只有最高项低置信度或违背已批 Brief 时才展示备选。 |
| 修复问题后人工再触发检查 | QA 自己承担“发现→批准范围内修复→重渲→复检”闭环；同一问题最多修复复检两次，一次运行最多三轮。失败原因和风险留在审片记录中。 |
| 人工记得收数据、改进下一期 | 定时学习作业读取授权数据，形成一条标注证据的实验建议；不允许凭单条视频改栏目规范。 |

## 人工只需要发送的三条消息

每道关只收到一屏“决策简报”：推荐结论、一句观众承诺、改动、未解风险、产物链接。不要把中间文件清单抛给制作人。

1. **内容**：`内容通过`，或 `退回：<一条合并后的修改意见>`。
   - 简报包括：选中角度、前 15 秒承诺、证据例外、完整口播和审稿结论。
2. **成片**：`成片通过`，或 `退回：<时间码 + 修改要求>`。
   - 简报包括：审片版、QA 摘要、事实/权利例外、默认标题及 16:9 / 4:3 / 3:4 原生封面。未改变已批内容的问题自动修复后回到这一关。
3. **发布**：`发布通过`，或 `退回：<设置或文案修改>`。
   - 简报包括：已生成的平台草稿、建议发布时间、标题、封面、简介、标签和确切平台/账号。平台最终发布点击与发布记录始终由人工掌控。

若用户在同一关分几条消息反馈，控制器先收齐后做一次完整修订，不为每条意见另开子流程。

## 控制器脚本

将以下文字作为主 VideoSpec 控制器的行为契约：

```text
当用户开始或继续一条视频时，识别当前 production 及最后有效审批。连续完成所有
非人工阶段；不要要求用户选择工具、产物、Agent 或下一步。把相互依赖的工作批处理为：

1）选题 + 内容；2）制作 + QA + 发布包预制；3）发布草稿；4）发布后学习。

只在内容审批、成片审批、发布审批、真实缺少外部依赖，或限定次数后仍有阻塞性 QA 失败时暂停。每个关口只给一份决策
简报和一个默认建议，不要求用户翻看过程文档。制作前检查所需外部能力；对仍在已批范围内的问题按 QA 重试上限自动修复并复检；
若修复改变已批的主张、口播、承诺或关键创意方向，只使受影响的关口失效并回到该关。

完整 TTS 前锁定全部口播和场景顺序；TTS 后以实测音频时长更新分镜、字幕与渲染，绝不
为了对时改写已锁口播。在制作 QA 中生成标题、原生比例封面、简介和标签，让它们在成片
关与真实成片一起核验。只有人工明确授权后才能发布。只使用真实且授权的分析数据；把
推测明确标为推测，并在证据充分时才改变可复用的长期规范。
```

## AI 选题策略

写稿前，选题引擎按以下公式评分：

`观众紧迫度 × 可执行收益 × 证据强度 × 栏目匹配 × 视觉可拍性 − 主张/风险成本`

最低准入条件：

- 标题承诺能在前 15 秒回答，并在全片前 20% 实质兑现。
- 观众带走一个决策、清单、对比或工具，而非只有解释。
- 时效性财经主张须有来源、日期、地区和口径；缺少支持会降分或禁止进入脚本。
- 源材料选题须保留其要求的论点和实质单元；改写不能悄悄换题。
- 前两名在既定置信度差内时，才在内容关展示两案；否则自动采用最高分项。

## 巴菲特九原则项目的边界

被引用的项目已经记录“内容通过”和“成片通过”，且已有完整 TTS；因此口播已锁定。流程优化不能随意改写其脚本，真实脚本变更必须建立新版本并重新经过内容关。它剩余的操作应是：准备好的发布包、明确的发布审批/发布记录，以及已授权的分析数据；不应再发生人工逐项触发 TTS、分镜或 QA 的操作。
